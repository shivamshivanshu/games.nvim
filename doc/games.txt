1. INTRODUCTION                                                    *games-intro*

games.nvim renders boards in Neovim buffers and talks to a Go game server
over TCP (NDJSON). The server owns all state and rules; the plugin renders
what it is sent and forwards your input. Only chess exists today.

Requires Neovim 0.11+. The server needs Go 1.26+ to build.

==============================================================================
2. INSTALL                                                        *games-install*

lazy.nvim: >lua
    {
      "shivamshivanshu/games.nvim",
      cmd = "Games",
      opts = {
        server = { host = "games.example.net", port = 7777 },
        username = "alice",
        password = function()
          return os.getenv("NVIM_GAMES_PASSWORD")
        end,
      },
    }
<
`username` and `password` may be left out; the first `:Games` then prompts for
them (|games-credentials|). Other plugin managers: call
`require("games").setup({...})` after the plugin is on 'runtimepath'. Native
packages: >
    git clone https://github.com/shivamshivanshu/games.nvim \
      ~/.local/share/nvim/site/pack/games/start/games.nvim
<
Run `:helptags ALL` once after a native install; lazy.nvim and packer generate
tags themselves.

3. CONFIGURATION                                                   *games-config*

Passed to `require("games").setup({opts})`.

    Option          Type                       Default        ~
    `server.host`     string                     `"127.0.0.1"`
    `server.port`     integer 1-65535            `7777`
    `username`        string, optional           prompted
    `password`        string or `fun(): string`    prompted
    `autoconnect`     boolean                    `true`
    `glyphs`          `"unicode"` or `"ascii"`       `"unicode"`
    `palette`         `"theme"` or `"vivid"`         `"theme"`
    `highlights`      table of group -> attributes `{}`

`password` as a function is called at each connect, never during setup(), so
the secret need not live in your dotfiles.

                                                              *games-credentials*
When `username` or `password` is missing, the first |:Games| prompts for the
username with |vim.ui.input()| and for the password with |inputsecret()| (not
echoed), keeps them for the session, then runs the command once connected.
Autoconnect is skipped when no username is configured.

`autoconnect` connects after |VimEnter| (or on the next tick if Neovim has
already started). A bad login or protocol mismatch stops auto-reconnect and
notifies; fix the config and restart Neovim (or call setup() again).

                                                 *games-palette* *games-highlights*
`palette = "theme"` derives every group from your colourscheme, taking only
one attribute from each source (e.g. `GamesLastMove` takes the background of
|hl-Search|, not its foreground), and derives them again on |ColorScheme|.
Of the two square shades it derives, the lighter becomes `GamesSquareLight`.
`palette = "vivid"` is a fixed lichess-style board: light `#f0d9b5`, dark
`#b58863`, last move `#cdd26a` and `#aaa23a`, check `#e05050`, and both sides
in near-black `#1b1b1b` ink, like a printed diagram. It needs 'termguicolors';
without it the plugin notifies once and uses "theme". Under every palette white
pieces are the hollow glyphs and black the solid ones; `glyphs` changes no
colour.

Board cells stack groups (|nvim_buf_set_extmark()| `hl_group` list): a cell
is {square, piece, mark}, so a mark tints the square and the piece keeps its
colour. Each group sets only the attribute of its role:

    Role            Groups ~
    background      `GamesSquareLight` `GamesSquareDark` `GamesLastMove`
                    `GamesLastMoveDark` (over `GamesLastMove` on dark squares)
                    `GamesCheck` `GamesWin` `GamesHit` `GamesPresent` `GamesMiss`
    foreground      `GamesPieceWhite` `GamesPieceBlack` `GamesSeat1`-`GamesSeat4`
                    `GamesKey` `GamesLabel` `GamesMuted` `GamesWon` `GamesLost`
                    `GamesDrawn` `GamesClockLow` `GamesCheckSign`
    ink (fg)        `<background group>Ink`, e.g. `GamesLastMoveInk`
    badge (both)    `GamesYourTurn`

Each ink is dark or light text, whichever contrasts more with its background
group. It is stacked over that background where text has no colour of its
own: empty squares, and the latest move in the move list. Inks are recomputed
whenever the palette is applied, at setup() and after every |:colorscheme|,
not on a live `:hi` of a background group.

`highlights = { GamesX = {...} }` always replaces the palette's definition of
GamesX and is passed to |nvim_set_hl()|, cut to the group's role: a background
group keeps only `bg` and `ctermbg`; a foreground group keeps `fg`, `ctermfg`,
`bold`, `italic` and `underline`. `{ link = "Group" }` is resolved to that
group's attributes and cut the same way. Anything cut is reported once.

The palette's own definitions never replace a group someone else has set since
the plugin last defined it: a plain `:hi GamesX`, or a colourscheme that
defines Games* groups. A colourscheme's Games* groups are its author's choice
and are kept as they are, roles unchecked. >lua
    require("games").setup({
      palette = "vivid",
      highlights = { GamesLastMove = { bg = "#9bc700" } },
    })
<

4. COMMANDS                                                      *games-commands*

                                                                       *:Games*
:Games                  Open a menu of the subcommands. Pickers use
                        |vim.ui.select()|, so a picker plugin (telescope,
                        snacks, fzf-lua) gives fuzzy search.

:Games challenge [game] [user...]
                        Challenge one or more users. Without users, prompts
                        for opponents one at a time ("done" ends the list),
                        then for a game that fits that many players, then
                        for options.

:Games challenges       Pick a pending challenge: accept or decline
                        (incoming), or cancel (outgoing).

:Games list [ongoing|finished]
                        Pick a game and open its board. Default `ongoing`.

:Games stats [user]     Win/loss/draw float. Default: you.

:Games leaderboard [game]
                        Leaderboard float, optionally for one game type.

:Games next             Open the next game waiting on your move.

Incoming challenges, and moves in boards you are not viewing, arrive as
|vim.notify()| messages. Accepting a challenge opens the board when the game
starts.

==============================================================================
5. BOARD KEYS                                                       *games-keys*

Buffer-local, Normal mode, in a `games://` board buffer. Only keys valid for
the current state are mapped; the footer lists them.

    Key     Action ~
    m       enter a move (chess: SAN or UCI)
    R       resign (confirms)
    D       offer draw (the opponent's D agrees)
    X       decline draw
    A       abort
    C       claim draw (chess)
    F       flip board (chess)
    ]g      next game waiting on your move
    q       close

==============================================================================
6. HEALTH                                                          *games-health*

>vim
    :checkhealth games
<
Reports: Neovim version (0.11+), whether setup() was called, the effective
configuration (password masked), connection state and last error, whether
glyph rendering works (if not, try `glyphs = "ascii"`), and the palette with
'termguicolors'.

==============================================================================
7. RUNNING AND JOINING A SERVER                                    *games-server*

Joining: get an account and the server address from whoever hosts it, set
`server.host` / `server.port` (|games-config|), then run |:Games|. There is no
self-registration.

Hosting (needs Go 1.26+): >sh
    go install github.com/shivamshivanshu/games.nvim/server/cmd/games-server@latest
    games-server adduser alice          # prompts for a password
    games-server serve --addr 100.64.0.1:7777
<
From a checkout, `make build` produces `bin/games-server` instead.

`serve` flags:

    Flag            Default            Meaning ~
    `--addr`          `127.0.0.1:7777`     listen address
    `--db`            `games.db`           SQLite file
    `--heartbeat`     `15s`                heartbeat interval
    `--idle`          `45s`                idle timeout before a client is dropped

`adduser [--db games.db] [--password-stdin] <name>`: `--password-stdin` reads
the password from one line of stdin. Use the same `--db` as `serve`.

==============================================================================
8. SECURITY                                                      *games-security*

Transport is plain TCP, no TLS: username, password and game traffic are
readable by anyone on the path. Passwords are stored as bcrypt hashes.

For anything beyond localhost, bind `--addr` to a Tailscale or WireGuard
address, or keep the default and use an SSH tunnel: >
    ssh -L 7777:127.0.0.1:7777 host
<
Use a password you use nowhere else.

Failed logins are locked out per IP: 5 failures in 5 minutes locks that IP
out for 5 minutes.
